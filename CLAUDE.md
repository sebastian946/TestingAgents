# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

SaaS for agent-assisted web testing: takes a site URL, crawls it, generates test scenarios with an LLM, and produces a report. The repo currently holds "Paso 1 (Motor MVP)": FastAPI API + PostgreSQL + Redis/RQ worker running a LangGraph pipeline. The task board lives in Notion (link in README.md); task IDs like WTA-4 refer to it. Code comments, docstrings, error messages, and docs are written in English (the Notion board itself is in Spanish).

## Commands

The Python project lives in `app/`, not the repo root. **Run Python commands from `app/`**: imports are rooted there (`from db.conn import ...`), and `config/variables.py` loads `env_file="../.env"` relative to the working directory, so running from elsewhere fails to find settings.

```bash
# From repo root: Postgres 16 (host port 5433) + Redis 7. --env-file is required because the compose file is in app/ and .env is at the root.
docker compose --env-file .env -f app/docker-compose.yml up -d

cd app
uv sync                            # install deps into app/.venv (Python 3.12)
uv run alembic upgrade head        # apply migrations (alembic/versions, WTA-4); init_db = create_all + stamp head (dev shortcut)
uv run alembic revision --autogenerate -m "x"   # draft a migration from model changes; review it, never edit a merged one
uv run uvicorn main:app --reload   # API at http://127.0.0.1:8000/docs, health at /Health
uv run python -m worker.worker     # RQ worker (separate terminal); runs worker/tasks.py
uv add <pkg>                       # add a dependency; commit pyproject.toml and uv.lock together
uv run playwright install chromium # once per machine; the Playwright tests and the worker need the browser build matching uv.lock
uv run pytest                      # tests (app/tests/); they spin up a local HTTP server, no DB or internet needed
uv run pytest tests/test_explorer.py -k robots   # single file / test
uv run pytest -m integration -v   # end-to-end: starts postgres+redis (compose), API + worker processes, local site; ~20 s
uv run python -m agents.designer_eval --version v2   # Designer prompt eval: REAL API calls (costs money, asks first); results in reports/designer_eval/
uv run python -m agents.designer_eval --model claude-sonnet-5-5   # same eval on another model (ADR-02); --compare prints saved runs, no API calls

# Fully containerized alternative (from repo root). Dockerfile targets: `api` (slim) and `worker` (adds Chromium only).
docker compose --env-file .env -f app/docker-compose.yml up -d --build
docker compose --env-file .env -f app/docker-compose.yml exec worker python -m worker.check_browser   # Playwright smoke test
```

Tests use pytest (`app/tests/`, run from `app/`). `tests/conftest.py` has an autouse safety net (`no_real_anthropic_api`: fake key, `ANTHROPIC_BASE_URL=http://127.0.0.1:9`, `designer_max_retries=0`) so no test can reach the real API; keep it. LLM mocking has three levels: HTTP transport with `httpx2.MockTransport` and the real SDK (`tests/test_designer_http.py`, `ScriptedAnthropic`, use `retry-after-ms: 1` on error responses to keep SDK retries instant), the SDK method (`FakeClient` in `tests/test_designer.py`), and our wrapper (`fake_designer`). Shared sample pages: `login_page_info`, `login_page`, `contact_page`. SSRF tests (`tests/test_ssrf.py`) replace `ssrf.socket.getaddrinfo` with a table; never let them hit real DNS. No linter or formatter is configured yet. Pyright/Pylance is pointed at `app/.venv` via the root `pyrightconfig.json`.

`.env` is copied from `.env.example`. `DB_PORT` is 5433 on purpose to avoid colliding with a locally installed Postgres. Postgres credentials are fixed when the volume is first created; changing them requires `docker compose ... down -v`.

## Architecture

Async job pattern: `POST /jobs` only inserts a `job` row with status `queued` and returns 202. The actual work (crawl, LLM, report) will be done by a separate RQ worker process; clients poll `GET /jobs/{id}`. API and worker share state **only through the database**, never in memory.

Layers (all under `app/`):
- `main.py` — FastAPI app, CORS from `CORS_ORIGINS` (credentials only without `*`), `/Health`, includes the auth and jobs routers; refuses to start without `AUTH_SECRET_KEY` and warns when it is short/the placeholder.
- Auth (WTA-26, ADR-07) — `security/auth.py`: argon2id via `pwdlib`, HS256 JWT via `pyjwt` (`sub` = user id, `exp`), `get_current_user` dependency (401 + `WWW-Authenticate: Bearer`; `HTTPBearer(auto_error=False)` so a missing header is a 401, not 403). `routes/auth_routes.py`: `/auth/register` (201, token), `/auth/login` (401 never says which field), `/auth/me`. The whole `/jobs` router has `dependencies=[Depends(get_current_user)]`; `owned_job` is the path dependency that loads a job scoped to the caller (`db_crud.get_user_job`) and 404s otherwise, so handlers never look a job up by id alone. `POST /jobs` sets `user_id` and enforces `AUTH_MAX_JOBS_PER_HOUR` (`count_jobs_since`, 429 + `Retry-After`). `job.user_id` is nullable only for pre-WTA-26 rows (documented ALTER in the guide). Tests: `tests/test_auth.py`; API tests call `tests.conftest.sign_in(client)` (registers through the API, sets the bearer header, returns the user id to pass as `user_id` when creating jobs in the DB); the integration test registers a real account and `http()` sends the token (`auth=False` to skip).
- `routes/routes.py` — `/jobs` endpoints; get a session via `Depends(get_db)` and delegate to `db_crud`. `POST /jobs` stores `description` (blank -> NULL); the Designer receives it. `GET /jobs/{id}/report` (WTA-20) serves the .xlsx with `FileResponse` and a `download_filename` name; job states map to: done -> 200, queued/running -> 409 + `Retry-After` + `detail={status, message}`, failed -> 409 with the reason, unknown id -> 404 (keep 404 only for a missing resource). The file path comes from `report_file(settings.reports_dir, job.id)`, never from `job.report_path`; a done job with a missing file is rebuilt with `generate_report` and `db_crud.set_report_path`. Covered by `tests/test_report_endpoint.py`.
- `models/models.py` — Pydantic request/response schemas (`*Read` use `from_attributes=True`). SQLAlchemy models are never returned directly.
- `db/conn.py` — engine (`echo=settings.sql_echo`, logs SQL; off in prod), `local_session`, `Base`, `get_db` dependency.
- `db/models_db/models_db.py` — SQLAlchemy 2.0 typed models: `job` (UUID PK) → 1:N `pages` → 1:N `scenarios`; deleting a job cascades. `status` is the `JobStatus` enum (Postgres type `job_status`). `steps` uses a JSON/JSONB variant so tests can run on SQLite.
- `db/db_crud.py` — all DB operations. Every function takes `db: Session` as a parameter (no global session). Already contains the worker-facing functions for upcoming tasks: `mark_job_running` / `mark_job_done` / `mark_job_failed` (state transitions + timestamps), `create_page` (also increments `pages_crawled`), `create_scenarios` (assigns per-job `SC-001`… codes and increments `total_scenarios`).

Conventions in `db_crud.py`: counters are incremented with an atomic SQL expression (`Job.pages_crawled + 1`) in the same transaction as the insert, and the explorer commits once per page so partial crawls stay consistent if the worker dies.

- `db/redis/redis_conn.py` — Redis client + RQ queue. `add_new_job_to_queue` enqueues the task by import string (`"worker.tasks.process_url_task"`) so the API never imports worker code (avoids a circular import). Only the job id travels through Redis.
- `worker/worker.py` — starts the RQ worker (`Worker`, which forks per job, where `os.fork` exists; `SimpleWorker` on Windows, where the default one crashes on the first job); `worker/tasks.py` — `process_url_task` marks the job running in a short session and runs `graph.testing_graph.invoke({job_id, url, description})`; it only catches real exceptions (marks failed, re-raises for RQ). Since WTA-21 the steps below live as nodes in `agents/graph.py` (explorer -> designer -> documenter, plus `fail`), with conditional edges `route_after_explorer` (no pages -> fail) and `route_after_designer` (no scenarios -> fail): those failures return normally, not as exceptions. State is `agents/state.py` `TestingState` (plain JSON-able data only; each node returns only the keys it owns, enforced by `tests/test_graph.py`). Tests replace collaborators on the `agents.graph` module (`graph.crawl`, `graph.design_pages`, `graph.local_session`, `graph.settings.reports_dir`), not on `worker.tasks`. Historically: it runs the Explorer, persisting each page through an `on_page` callback (`db_crud.create_page`, one commit per page). Live progress (WTA-14) depends on two rules there: each page uses its own short `with local_session()` (the main session is `close()`d before the crawl), so no connection sits `idle in transaction` during minutes of browser I/O; and `mark_job_running` deletes the previous attempt's scenarios/pages and resets counters in the same commit as the status change, so retries never duplicate pages. `tests/test_progress.py` covers both against a SQLite file with two connections. After the crawl (browser closed), WTA-17 runs `design_pages(pages, job.description, on_result=persist_scenarios)`: each page's scenarios go through `db_crud.create_scenarios` in their own short session (rows and `total_scenarios` increment in one commit, codes `SC-NNN` continue across pages), linked via the `page_ids` dict that `persist_page` fills (crawled url -> `pages.id`). Pages without scenarios are listed in `job.error` of a `done` job (`mark_job_done(error=...)`); zero designed pages or a `DesignerFatalError` fails the job (pages kept). `tests/test_scenarios.py` covers this; worker tests must use the `fake_designer` fixture (`tests/conftest.py`) so no test calls the API. Then the Documenter (WTA-19) writes `reports/{job_id}.xlsx` in its own short session and the job is marked `done` with `report_path` (a retry deletes the old file first); report failures fail the job.
- `agents/explorer.py` — `crawl(start_url, max_pages=8, timeout=15, on_page=None, use_browser=False)`: deterministic same-domain BFS (ADR-01: no LLM here). One `_bfs` loop, two fetchers: `RequestsFetcher` (static HTML, default, used by most tests) and `PlaywrightFetcher` (`use_browser=True`, what the worker uses): one headless Chromium per crawl, images/fonts/media blocked, `domcontentloaded` + best-effort 3s `networkidle`, and it fills `CrawledPage.elements`. Guardrails: anti-SSRF check on every URL before fetching, robots.txt via `protego` (the stdlib `urllib.robotparser` ignores wildcards, which most real sites use), `User-Agent: WebTestAgent/0.1`, per-page timeout that skips the page rather than aborting, non-HTML responses skipped, off-site redirects dropped. `normalize_url` drops fragment and query string on purpose (`/items?page=2` counts as `/items`).
- `agents/page_info.py` — the `PageInfo` inventory stored in `pages.elements` (JSONB) and later fed to the Designer instead of raw HTML: forms (fields with tag/type/name/id/label/placeholder/required/options, submit text), buttons outside forms, main nav links, h1/h2. Extracted by ONE `page.evaluate(EXTRACT_JS)` returning plain JSON (never DOM handles or `outerHTML`); hidden elements, scripts and styles are skipped, every list is capped and `to_dict()` drops empty values so a page stays well under 2KB. Label lookup handles `for`, wrapping labels, `aria-label(ledby)`, the React `<id>-label` convention and a sibling label in the same group; a `<button type="button">` inside a form counts as its submit when no real submit exists. Fields outside any `<form>` become one *virtual form* (`virtual: true`, JS-driven logins); buttons of forms without fields (bare "Add to basket") are listed as page buttons. `PageInfo.signals` carries counters for classification (`price_count`, `stock_words`, `link_count`, `max_similar_links`, `word_count`, `repeated_button_max`).
- `agents/designer.py` — `design_scenarios(page, description) -> DesignResult` (WTA-15): one Claude call per page via the official `anthropic` SDK (`client.beta.messages.create` with `output_config.format` = the `DesignerOutput` JSON schema), then `DesignerOutput.model_validate_json` on our side for the rules the API cannot enforce (non-blank text, min 1 step, unique titles, max 12). WTA-16: a failed validation gets exactly ONE self-healing retry, a fresh single-turn request carrying the invalid response and the errors (never replay the assistant turn: thinking blocks are bound to their conversation). Transient API errors (429/529/5xx/timeouts) are retried by the SDK itself (`DESIGNER_MAX_RETRIES`, `DESIGNER_TIMEOUT`); do not add a manual backoff loop. `DesignerError` = this page has no scenarios, the job continues (`design_pages` collects one `PageDesign` per page); `DesignerFatalError` (auth, permission, unknown model, 400) stops the run. `MODEL_PROFILES` lists per model which optional fields it accepts (Haiku 4.5 rejects `effort`; fallbacks only on Opus 5.5 / Sonnet 5.5) and its prices for `DesignResult.estimated_cost_usd`; add an entry when adding a model. The model decision lives in `docs/adr/ADR-02-designer-model.md` (provisional until the eval is run with a real key). Model/effort/prompt version come from `DESIGNER_*` settings (default `claude-opus-5-5`, effort `high`, prompt `v3`). Do not add `temperature`: current models reject sampling params (400). The system prompt must stay static (it is cache-marked); per-page data goes only in the user message, fenced in XML tags, with the page inventory declared untrusted data. `fallbacks="default"` + beta `server-side-fallback-2026-07-01` handles refusals. Prompts live in `agents/prompts/designer/vN/{system,user}.md` (`string.Template`, `$vars`); never edit a released version — add `vN+1` and a CHANGELOG entry, and compare with `agents/designer_eval.py`. `ANTHROPIC_API_KEY` is optional in `Settings` so nothing else needs it. Called by the worker since WTA-17 (see `worker/tasks.py` above). `agents/prompt.py` is a superseded draft. Tests use a fake client (`tests/test_designer.py`), never the network.
- `llm_calls` table / `LlmCall` model (WTA-18) — one row per billed Anthropic call (failed ones too: invalid, refusal, max_tokens), written by `log_llm_call` in `worker/tasks.py` through `design_pages(on_call=...)` -> `design_scenarios(on_call=...)` -> `CallUsage`. Job totals are SUMs: `db_crud.get_job_usage`, `GET /jobs/{id}/usage`. `cost_usd` (Numeric in Postgres, Float variant in SQLite) is fixed at call time from `estimate_cost_usd` / `MODEL_PROFILES` (cache writes 1.25x, reads 0.1x); unknown model -> NULL, counted in `calls_without_price`. Price the served model (`CallUsage.model`), not the requested one: a fallback can switch it. `mark_job_running` keeps the previous run's calls (paid) with `page_id = NULL`. Never sum tokens only from successful `DesignResult`s: retries and failures are billed. `tests/test_usage.py` covers it; the conftest `FakeDesigner` emits `on_call` too.
- `agents/documenter.py` (WTA-19) — `build_workbook(job, pages, scenarios)` is pure (plain `Report*` dataclasses -> openpyxl `Workbook`, sheets Summary + Scenarios); `generate_report(db, job_id, reports_dir)` loads from the DB and saves atomically (`.tmp` + `os.replace`) to `report_file(reports_dir, job_id)`. Totals are computed from the same scenario list written to the sheet, never queried separately. Always write cells through `_put`: it strips `ILLEGAL_CHARACTERS_RE`, forces strings starting with `=` to `data_type='s'` (page titles and LLM text are untrusted: formula injection), converts aware datetimes to naive UTC (Excel has no timezones) and refuses `MergedCell`s. Row heights are set explicitly (`_lines_needed`) because not every app auto-fits wrapped rows. The report is customer-facing: no LLM cost in it. `tests/test_documenter.py` covers it.
- LangSmith tracing — `config/variables.py` `export_langsmith_env` copies every `LANGSMITH_*` from `.env` into `os.environ` with `setdefault` (the SDK only reads the environment; existing env values win) and exposes `TRACING_ENABLED` (forced off when there is no API key). LangGraph traces the graph/nodes by itself; `designer._default_client` wraps the Anthropic client with `langsmith.wrappers.wrap_anthropic` only when tracing, so each Claude call is an `llm` child run (needs langsmith>=0.14.7: 0.14.4 breaks on anthropic 1.x, no `client.completions`). `worker/tasks.py` passes `_trace_config` (run_name `job <id>`, tags, metadata) to `invoke` and flushes traces in `finally` (forked RQ children exit right after the job). `tests/conftest.py` sets `LANGSMITH_TRACING=false` before any import: keep that first. `worker/worker.py` reconfigures stdout/stderr to UTF-8 (SQLAlchemy `echo=True` logs LLM text; cp1252 consoles crash on characters such as an arrow). Covered by `tests/test_tracing.py`.
- Integration test (WTA-24) — `tests/test_integration.py`, marker `integration`, excluded from the default run by `addopts` in `pyproject.toml`. It starts the API and the worker as subprocesses with env overrides: `DB_NAME=testing_agents_it` (own DB, truncated each run), a unique `RQ_QUEUE_NAME`, a temp `REPORTS_DIR`, `DESIGNER_MODE=fake` (`agents/fake_designer.py`: deterministic scenarios from the inventory; the switch is at the top of `design_scenarios`, and `design_pages` builds no client in fake mode) and `SSRF_ALLOWED_HOSTS=["127.0.0.1"]` for its local site. Both are test-only settings: default `anthropic` and `[]`; the worker prints a warning in fake mode. Every wait goes through `wait_until` (polling with a timeout), never a fixed sleep; on Windows `kill_tree` uses `taskkill /T` because the venv launcher spawns a child. Unit tests for the switches: `tests/test_fake_mode.py`.
- Languages — `config/languages.py` (`Language = Literal["en", "es"]`, `LANGUAGE_NAMES` for the prompt). `job.language` (String(5), server default `en`) comes from `POST /jobs` and travels in `TestingState.language` -> `design_pages(language=...)` -> `render_prompt(..., language)`, which fills `$language` in prompt v3's user message (`<output_language>`); the system prompt stays language-free so it is cached for both. The report reads `job.language`: every human-facing text is in `agents/report_texts.py` (`texts(lang)`, `display(code, lang)` translates priority/category/page-type codes). Codes stay English in the DB and the API. A running worker does not reload code: restart it after changes (a stale worker on the same queue silently runs old code). Covered by `tests/test_language.py`.
- `agents/page_classifier.py` — `classify_page(info) -> PageType` (login, signup, checkout, product, listing, form, content), pure function, rules ordered first-match-wins and documented in the module docstring and `docs/guide.md` ("Page type rules"). Thresholds are module constants. `PlaywrightFetcher.fetch` stores the value in `FetchResult.page_type` → `CrawledPage.page_type` → `pages.page_type`; `RequestsFetcher` leaves it `None`. When a real page is misclassified: add it to `tests/test_page_classifier.py` as a unit case with its signals, then tune.

Inside Docker, hosts are service names: compose overrides `ENDPOINT=postgres`, `REDIS_HOST=redis`, `DB_PORT=5432`; `.env` keeps `localhost`/`5433` for running outside Docker.

Docs (WTA-25): `README.md` is the short entry point (pitch, Mermaid diagrams, Docker quick start, the 3 main endpoints, ADR summaries, roadmap); `docs/guide.md` is the full technical guide; `docs/adr/ADR-0N-*.md` hold the design decisions (context -> decision -> consequence). Add a new ADR file and a row in the README table for each new decision. Mermaid blocks must render on GitHub: quote labels that contain punctuation.

Docker: `app/docker-compose.yml` uses healthchecks, the `api` runs `alembic upgrade head` before uvicorn and the worker waits for a healthy api, so `up -d --build` on a fresh clone works with no manual step. Production (`docs/deployment.md`) adds `app/docker-compose.prod.yml` on top: `ports: !reset []` on postgres/redis/api, Redis `--requirepass ${REDIS_PASSWORD}` (settings `redis_password`), `SQL_ECHO=false`, and a `caddy` service built from `frontend/Dockerfile` (Vite build copied into `caddy:2-alpine` at `/srv`; `app/deploy/Caddyfile` serves it with `try_files {path} /index.html` and proxies `/auth/* /jobs* /Health /docs*` to `api:8000`, HTTPS for `${DOMAIN}`). `app/deploy/backup.sh` is the nightly `pg_dump` cron.

Frontend (`frontend/`, React 19 + Vite + TypeScript + Tailwind 4): `npm run dev` on :5173 proxies `/auth`, `/jobs`, `/Health` to :8000 (`vite.config.ts`), so no CORS locally. `src/api.ts` is the only place that calls `fetch` (bearer header from `localStorage`, FastAPI `detail` -> message, 401 on a private route drops the session via `onUnauthorized`); `src/auth.tsx` holds the session (`AuthProvider`, `RequireAuth`); pages in `src/pages/`. Design (WTA-31): the Tests Wise design system (Design System artifact) is implemented as CSS variables + component classes in `src/index.css` (`@theme inline` mirrors the colors into Tailwind; dark theme = `prefers-color-scheme` overriding the variables) and copied, without Tailwind, in `public/landing.css` for the static pages; keep both in sync when a token changes. No `slate-*`/`indigo-*` utilities: use the classes (`btn-primary`, `card`, `badge badge-done`, `notice notice-warning`, `table`, `scenario`, `plan`, `stat`) or the `--token` variables. Fonts come from Google Fonts (`index.html`, `landing.html`); the Caddy CSP allows `fonts.googleapis.com` / `fonts.gstatic.com` and forbids inline scripts, so the landing's language switch is `public/landing.js`. Caddy rewrites `/` -> `landing.html`, `/terms`, `/privacy` and redirects `/pricing` -> `/#pricing`; SPA routes are `/dashboard`, `/new`, `/job/:id`, `/billing`, `/account`, `/login`, `/register`, `/verify`, `/forgot-password`, `/reset-password`: never start one with `/jobs`, `/auth`, `/billing/` (the Vite proxy key is the regex `^/billing/`, so the `/billing` page stays in the SPA), `/Health` or `/docs`, because the Vite proxy and the Caddyfile forward those prefixes to the API (a page refresh there would get JSON). Plans: Free 3, Starter 10/US$19, Pro 40/US$49 (`config/plans.py`, the landing and `BillingPage` must agree). Plan handoff: landing plan buttons link to `/register?plan=<code>`; `AuthForm`, `LoginPage` and `RegisterPage` keep `?plan=` and land on `/billing?plan=<code>`, where `BillingPage` redirects once to that plan's hosted checkout (or shows a notice when payments are not configured / the plan is current). `public/landing.js` also reads the SPA token (`testing-agents.token`), calls `/auth/me` and swaps the header to the account + Dashboard (`data-anon`/`data-auth` elements) and points `data-plan` buttons to `/billing?plan=`. Dockerfiles stay on `python:3.12-slim` and an LTS `node`; Dependabot ignores major/minor bumps of those. Lists poll every few seconds only while a job is queued/running. The report is downloaded as a blob because a link cannot send the header. Tailwind 4: shared classes are `@utility` in `index.css` (`@apply` cannot use custom classes). `npm run build` (tsc + vite) and `npm run lint` (oxlint) must pass; `tsconfig` has `erasableSyntaxOnly`, so no parameter properties in classes.

Migrations (WTA-4): `alembic/env.py` takes the URL from `db.conn.DATABASE_URL` (never from alembic.ini) and `target_metadata = Base.metadata`; files are `NNNN_slug.py` (`file_template` in alembic.ini). 0001 = pre-auth schema, 0002 = users + job.user_id, 0003 = email verification. Old databases: `alembic stamp 000N` then `upgrade head`; `alembic check` must print "No new upgrade operations detected" after a model change + migration. Tests use SQLite `create_all`, not migrations.

Launch readiness (WTA-30): `db/redis/redis_conn.enqueue_options` gives every job `job_timeout` and `Retry` (WTA-8; `worker/tasks._failure_reason` appends "Retrying automatically" while `get_current_job().retries_left` > 0). `security/ratelimit.py`: `limiter.enforce(Limit, subject)` fixed windows in Redis, fails open on `RedisError`, `MemoryBackend` in tests (conftest sets it per test); client IP from `request.client.host` (uvicorn runs with `--proxy-headers` in compose). `security/passwords.is_pwned` (HIBP k-anonymity, fails open; conftest turns it off). `observability.init_sentry(component)` in `main.py` and `worker.py`. Billing (ADR-09): `config/plans.py`, `subscriptions` table (migration 0005) written only by `services/billing.apply_webhook` after `verify_signature` on the RAW body; `plan_for` decides entitlement; `POST /jobs` answers 402 past `usage_for(...).remaining`; `GET /billing/me`; conftest sets `default_plan="pro"` so other tests can create jobs, billing tests set `free`. `POST /billing/checkout {plan}` -> `billing.create_checkout` (Checkouts API when `LEMONSQUEEZY_API_KEY` + `LEMONSQUEEZY_STORE_ID`, else the share link + user data; 400 for free/unknown plans, 503 when nothing is configured) and the `BillingPage` redirects to it; `POST /billing/cancel` / `/resume` go through the provider API with `LEMONSQUEEZY_API_KEY` (`billing._api`, `requests.request`; tests replace it with `FakeProviderApi`) and answer 409 on `BillingError`; `Plan.trial_days` (Pro = 7) only labels the landing and the plan page, the trial itself is the variant's setting at the provider. `services/cleanup.py`: `delete_job_completely` (rows + `reports/{id}.xlsx` + `reports/{id}/`), `delete_account` (`db_crud.delete_user` returns the job ids), `purge_expired_jobs` run by a daemon thread in `worker.py` every 6 h (`RETENTION_DAYS`). `DELETE /auth/me` needs the password. Authenticated crawls (WTA-29, ADR-08): `POST /jobs` takes `login: {login_url?, username, password, authorized}`; the route checks `authorized`, `credentials.configured()` (503 without `CREDENTIALS_KEY`), anti-SSRF + same host for the login page, then stores `security.credentials.encrypt(LoginSpec)` in `job.login_credentials` (Fernet; `JobRead` exposes `login_url` only). The explorer node reads the blob in a short session, decrypts it, passes `login=`/`on_login=` to `crawl`, and `clear_job_credentials` in a `finally`; `mark_job_done`/`mark_job_failed` NULL it too and `worker.py` runs `clear_stale_credentials` at start. Credentials never go in the state (`login_note` carries only the failure message, which the documenter appends to `job.error`), logs, traces or prompts; `LoginSpec.__repr__` hides the password. `PlaywrightFetcher.login` is deterministic (visible password field, found directly, behind the site's login link (`LOGIN_LINK_WORDS`) or after a two-step identifier screen (`_find_login_form`, WTA-35); preceding text/email input; form submit or Enter; success = no visible password field afterwards) and never raises; the login page may be on a sibling subdomain (`explorer.same_site`, used by both routes); with `skip_unsafe=True` `_bfs` drops links whose path words hit `UNSAFE_LINK_WORDS` (`_looks_unsafe`, also matches split words like `log-out`; cart/checkout/pay words are NOT in it since WTA-35: viewing them is a GET). Tests: `tests/test_login_crawl.py` (module, API, graph clearing, Chromium against a cookie-session site); `OWNED_KEYS['explorer']` includes `login_note`. Frontend: optional login section in `NewJobPage` with the test-account warning and the authorization checkbox.
